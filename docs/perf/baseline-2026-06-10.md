## 2. 観察と分析

### 2.1 ISSUE-031 の効果 (確定)

- **新規アップロード経路で variant 事前生成が動作**: Network panel で `_preview.webp` (307KB, image/webp) を確認
- **`/` で LCP -51% (5/27 比)**: carousel 5 件のうち新規 1 件がトップに来るため、 LCP 要素が WebP variant
- **`/memory/[id]` で LCP -42% (5/27 比)**: 新規 memory の本画像が preview.webp (307KB) で配信

### 2.2 `/album` で LCP が横ばいの理由

- データ状態: 既存 49 件 (variant 未生成) + 新規 1 件
- 既存 memory は signed-url.ts の **fallback ロジック** で original (2〜4MB JPEG) を配信
- 49 枚の原寸 JPEG が並列ロード → 帯域圧迫で **LCP 要素が遅くなる**
- 真の効果を見るには **全件 variant 化 migration** が必要

### 2.3 LCP 削減の上限 (Lighthouse Simulated Throttling)

- /memory/[id] の本画像は 307KB の WebP
- Slow 4G simulated (1.6 Mbps): 307 × 8 / 1600 = ~1.5s で転送可能なはず
- それでも LCP 13.3s = 残り **~12s は JS waterfall (HTML → JS → API → URL → image)**
- → Server Component 化 (ISSUE-026/027) で waterfall を圧縮しないと、 これ以上の改善は難しい
- 実機 (非 simulated) では LCP がさらに改善する可能性大

## 3. 残る課題

### 3.1 既存画像 migration (短期、 高 ROI)

50 件以下のテストデータならスクリプトで一括 variant 生成可能。 実装案:

```ts
// scripts/backfill-variants.ts
// すべての Image row を iterate → 既存 _thumb.webp が無ければ生成 + upload
```

これで `/album` LCP も大幅改善見込み。

### 3.2 JS waterfall の圧縮 (中期)

- ISSUE-017 (requireUser cache) で TTFB を削減
- ISSUE-026 / 027 (Server Component 化) で fetch → image の連鎖を HTML 内で完結
- ISSUE-021 (bundle analyzer) で JS bundle を可視化

### 3.3 実機 (非 simulated) での計測 (低工数、 必須)

Lighthouse Simulated Throttling は実体より厳しい。 実機の Chrome で:

- Slow 4G エミュレート (Network throttle)
- 4× CPU slowdown
- ハードリロード → DevTools Performance タブで実 LCP を測定

これで simulated と実機の乖離を把握できる。

## 7. LCP 要素の特定 (2026-06-10、 一時デバッグで判明)

PerformanceObserver で各ページの LCP 要素を直接ログ:

| ページ         | 最終 LCP 要素                | 種類         | サイズ (px²) |
| -------------- | ---------------------------- | ------------ | ------------ |
| `/album`       | `<p>` カード本文             | **テキスト** | 9,159        |
| `/`            | `<img>` carousel cover (4:5) | 画像         | 23,859       |
| `/memory/[id]` | `<img>` 本画像 (4:5)         | 画像         | 190,125      |

**重要な発見**:

- `/album` の LCP は **画像ではなくテキスト** → 画像最適化は構造的に効かない
- `/`, `/memory/[id]` は画像が LCP だが、 サイズが小さくなっても **fetch waterfall (HTML → JS → API → URL → image)** で paint 時刻が遅延 → 画像最適化だけでは秒台に届かない
