## 3. 観察と分析

### 3.1 Speed Index は大幅改善 ✓

3 ページとも -44〜46% の劇的な改善。 これは:

- **ISSUE-018 (BFF)**: /album で N+1 (50 並列 URL fetch) を排除 → 上半分の paint が速くなった
- **ISSUE-019 (transformation)**: サムネ 320px / preview 1024px で帯域節約 → 中間的なコンテンツがすぐ出る
- **ISSUE-030 (style 統一)**: 視覚への副次効果なし、 一貫性向上

### 3.2 LCP はほぼ横ばい (variance 内) ✗

「最大の要素」 = 主要画像が **依然遅い**。 数値からの分析:

- `/album`: LCP 9.5s
  - サムネ 50 枚 × ~30KB ≈ 1.5MB 合計
  - Slow 4G simulated 1.6 Mbps での転送時間: 1.5MB / 0.2 MB/s ≈ 7.5s
  - 他リソース競合と合わせて 9.5s ≈ 観測値と一致
- `/memory/[id]`: LCP 22.9s
  - preview 1024px の本画像 = 300〜500KB
  - waterfall (HTML → JS → /memories/{id} → /uploads/{id}/url → image)
  - JS bundle ~500KB gzip on Slow 4G ~2.5s
  - 累積 ~20s で観測値と整合

### 3.3 残る支配要因

1. **画像バイト数**: 320px / 1024px でもまだ重い → AVIF/WebP で更に 30〜50% 削減可
2. **画像発見の遅さ**: `<img>` が late discovery → `priority` hint / preload で前倒し可
3. **JS → fetch waterfall**: Client Component で JS 待ち → Server Component 化で短縮可
