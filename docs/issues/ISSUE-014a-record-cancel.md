## 目的 (Why)

ISSUE-014 で **集中フロー (`/record`) では BottomNav を非表示** にする方針を採用した。
結果として `/record` のフォームには「のこす」ボタンしか無く、 **キャンセル / 戻る方法が消失** した。

ユーザー実テストで以下の指摘:

> /record のフォームが表示されているが、こちらは のこす ボタンがあるのですが、キャンセルしたい場合、どのようにする？フッターのボタンも表示されていません。

入力中に「やっぱりやめる」ができないのは、Hana の設計原則 §1「Whisper not shout」「Forgive the user」に反する。
**集中させつつ、いつでも辞められる** バランスが必要。

## 設計判断

### 「やめる」ボタンの位置: 絶対配置・top-left

V0 §5.5 の back chevron pattern。Card 中央レイアウトを壊さずに副次操作を置ける。
warm-ivory pill (`bg-elevated` + `ring`) で「責めない」トーンを保つ。

### 未入力 ⇒ ダイアログ無しで即遷移

UX 原則「責めない」。何も入れていない時の余計な確認は摩擦になるだけ。
`hasUnsavedChanges = uploadedImage || title.trim() || body.trim()` で判定。
`recordedAt` (今日デフォルト) と `weather` (任意) は判定に含めない。

### 確認ダイアログを「外側クリック」で閉じない

AiConsentDialog と同じ設計。指の誤タップで作業を失わない。
明示的に「もうすこし なおす」または「とじる」を選ばせる。

### 「とじる」ボタンが destructive 色ではない理由

V0 §1「Whisper not shout」。本文は「失う」とは言わず「うしなわれます」とだけ伝える。
赤いボタンで脅すより、ghost で控えめに置くほうが Hana らしい。

## 動作確認手順

```bash
pnpm dev
# 1. /record を開く → 左上に「‹ やめる」が出る
# 2. 何も入れずに やめる → / に直接戻る
# 3. 画像をアップロード後 やめる → ダイアログ「ほぞんせずに とじますか？」
# 4. もうすこし なおす → ダイアログ閉じ、画像は残る
# 5. もう一度 やめる → ダイアログ → とじる → / に戻る
# 6. タイトルだけ入れて やめる → ダイアログ → とじる → /
# 7. ほんぶんだけ入れて やめる → ダイアログ → とじる → /
```
