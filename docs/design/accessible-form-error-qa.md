# 必須入力とエラー復帰 QA

## 対象

- `/onboarding`: 呼び名、うまれたひ、登録失敗
- `/record`: 写真、タイトル、本文、ひにち、保存失敗

## 自動回帰

- WCAG 2.4.3: 宣言した視覚順で最初のエラーへフォーカスし、対象がなければ概要へ戻す
- WCAG 3.3.1: エラー入力を `aria-invalid` と個別の説明で特定する
- WCAG 3.3.2: 必須項目を画面上の「必須」と `required` / `aria-required` で伝える
- 折りたたみ内の本文・日付エラーは、領域を開いてから対象へフォーカスする
- 入力値は失敗時に消去せず、修正後に Enter または送信ボタンで再送信できる

## 実ブラウザ確認

| 条件                   | 確認内容                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| 320 CSS px             | 必須表示、エラー概要、個別エラー、送信操作が横にはみ出さず、重ならない                     |
| 200% zoom              | エラー概要から入力、再送信まで読み順とフォーカス順が一致する                               |
| キーボード             | Tab / Shift+Tab / Enter だけで修正と再送信を完了できる                                     |
| スクリーンリーダー相当 | 必須、入力名、無効状態、個別エラーが一つの操作文脈で分かる                                 |
| 通常進捗               | loading / upload / AI生成の進捗は `status` のまま、ブロッキングエラーだけを `alert` にする |

## 実施結果

- 2026-07-29に `/onboarding` と `/record` を 320 / 390 / 430 / 768 CSS pxで実行し、10ケース成功
- 320 CSS pxを、640px表示領域を200% zoomした場合のreflow相当条件として確認
- DOM回帰で、キーボード再送信、入力保持、エラー関連付け、写真再選択・再試行後のフォーカスを確認
- 実支援技術ごとの読み上げ差は残余リスクとして扱い、正式公開前の端末確認対象にする

## 証跡の安全性

QA は固定の合成文言と空入力で行う。実写真、実名、メール、生年月日、画像 URL、
presigned URL、`storage_key`、prompt、AI 生成本文をスクリーンショット、ログ、PR本文へ含めない。
